# 数据库列表“描述”列中文乱码：修复设计

卡片：BUG-20261029-DESCRIPTION-MOJIBAKE
基线：qa/current 的 e60564035e72861be25dd9c9050ac5786df5ca53
入口：截图中的“数据库”页文件列表，用户于 2026-10-29 明确确认。

## 现状与原因

截图中 MP3 的 ID3 注释帧包含语言标记、简短说明和正文。当前读取器把整个帧当正文解码。现有素材库至少一条记录已经把 eng、UTF-16 标记和原始字节写入数据库“描述”字段，最后一个 ASCII 数字还缺失了 UTF-16 的零高字节。进一步只读核对实际音频发现，旧库后半段字节已损坏，无法只靠旧库还原；原音频仍可正确读出注释，源文件无需改动。公开测试使用独立合成样例。

## 模块一：新读取的注释

- 注释帧先跳过语言、简短说明及终止符，再按帧编码解码正文。
- 只改 ID3v2.3/2.4 的 COMM；标题、艺术家、路径等映射不变。ID3v2.2 保留原处理和 ID3v1 后备读取，避免混合标签文件丢失旧字段。
- 用中文、英文、空值和长正文样例，先验证旧实现失败，再验证修复。

## 模块二：旧库记录识别

- 按字段实际长度读取旧值；识别直接保存的旧注释帧字节，以及程序创建的 UTF-16 数据库把无效字节转换为替换字符后的特征。只有严格命中才标记需要原音频注释。
- 能从旧字节恢复时先给出尽力恢复值。若 UTF-16LE 正文仅缺最后一个 ASCII 字符的零高字节，再恢复该字符。数据库查询不打开原音频。
- 恢复值只供数据库列表“描述”格使用，不改日常数据库，也不改变其他页面。
- 普通 UTF-8、英文、空值和无法识别的旧值保持原样。

## 模块三：数据库列表的后台补正

- 仅数据库列表的后台线程，对严格标记的记录只读原音频注释；源文件可读且注释非空时，覆盖列表显示值，解决旧库中不可逆损坏的中文。请求携带界面实际显示范围，用户关键词搜索跳过额外读取；集合规则内部带关键词但仍属普通列表时保留补正。
- 后台线程按文件路径、库中大小和修改时间缓存读取结果，最多 512 项；30 秒后允许重试。网络路径不额外读取源音频；源文件不可读时保留旧库的尽力恢复值。
- 每条原音频读取前检查后台线程是否已停止，切库或关闭时不继续探测剩余文件。
- 专辑、播放列表、详情等共用数据库查询不读取源音频；切换数据库时后台线程重建，缓存随之清空。
- 每个标签页保存“上次实际执行的搜索词”，切回时和该页结果一起恢复。搜索框里尚未提交的文字单独保留；普通列表与关键词结果均按各自已执行的搜索决定是否补正描述。
- 未通过搜索语法检查的文字不改变已显示结果的范围；随机播放直接提交搜索时，同步记录它实际使用的搜索词。

## 验证与交付

1. 聚焦测试先红后绿；用程序直接创建的 UTF-16 库核对旧记录标记，并把专用测试注册进常规 CTest。实际后台查询测试核对数据库列表补正、用户关键词搜索跳过、集合规则保留补正、播放列表不读源注释和源文件不可读时的退路；混合 ID3v2.2/ID3v1 测试核对旧字段后备读取。标签页测试核对普通列表、关键词结果及未提交文字在切换后的各自状态。
2. 在本卡目录构建实际测试包，用隔离的真实库副本核对英文和中文源注释、库中旧值和界面显示；同时核对后台列表补正。
3. 包、报告、截图保存在本机验收目录；用户明确确认实际截图后才记前端验收通过。

不修改音频文件、日常数据库，不处理另一个“文件浏览器”入口。
