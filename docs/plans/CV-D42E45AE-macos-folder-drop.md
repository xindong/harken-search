# CV-D42E45AE · Mac 文件夹拖入扫描确认

## 来源、基线与范围

2026-11-04 核对 origin/qa/current 为 6573402de540c3d489b5a293d0cd7b6c45808be5。Windows 的 src/WindowsMain.cpp 中 WM_DROPFILES 会把存在的文件夹放进 pendingScanFolders，并打开扫描确认框，scanDialogAutoStart=false；扫描中会报告忙碌。Mac 行为合同明确外部拖放未接入。Windows 原 Cuevi 看板未迁到 Mac，本卡只以已合入 QA 的源码行为为来源，不声称已读取原卡或完成双向同步。

本卡只接通 Finder 向 Mac 主窗口拖入**一个或多个现有文件夹**，沿用共享扫描确认框。音频文件和 .db 文件拖放、向外拖放及 DAW 投递另卡处理；本卡不得假装支持这些类型。基于最新 QA 的独立 clone/分支，合入上卡待验收的 Mac 候选；不合入 QA/main，不改 Windows 的 WM_DROPFILES 或扫描器。

## 模块、输入输出及失败处理

1. Cocoa 视图注册文件 URL 拖入；仅当所有拖入项目都是本机现存文件夹时接受。读取有限数量、去重，不解析网络 URL、不打开文件。混合文件、音频文件、.db、无效 URL 拒绝且不得修改素材库。
2. AppState 只登记待扫描文件夹、显示现有确认框，并保持 scanDialogAutoStart=false。用户取消不入库；点击“开始扫描”才调用共享扫描工作流。扫描中沿用现有忙碌提示，不能偷偷排队或自动开始。
3. 隔离 QA 入口对相同接收逻辑喂入本卡目录下的 URL，记录实际 pendingScanFolders、确认框和扫描状态；不得有绕过确认的直接数据库写入。此入口仅在诊断 + 预览隔离构建启用。
