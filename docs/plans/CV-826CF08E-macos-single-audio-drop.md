# CV-826CF08E · Mac 拖入单个音频文件并入库试听

## 来源与范围

2026-11-04 核对 Mac Cuevi 看板：没有同题卡或活跃负责人；远端 `origin/qa/current` 为 6573402de540c3d489b5a293d0cd7b6c45808be5。Windows QA 的 `WM_DROPFILES` 接收音频文件，写入现有素材库并预载试听。原 Windows Cuevi 卡本机不可读，本卡以当前 QA 源码作行为来源，不称自动双向同步。独立 clone 起于最新 QA，顺序纳入尚待验收的 Mac 候选 10283a8876388360294657d5a020c99e254adabd；候选不等于已合入 QA。

本卡只实现**一个存在的本机音频文件 URL**从 Finder 拖到 Mac 主窗口：接受 Windows 已列出的扩展名，使用共享 `Database::readAudioRecordMetadataSnapshot`、`addFile` 和既有异步音频/波形入口，显示入库或失败提示。已有文件不重复入库；失败不留下伪成功记录。无素材库、扫描/切库繁忙时拒绝。文件夹确认扫描、.db 切库保持原行为。多文件、文件夹与文件混合、>200 文件降级扫描，以及工作站向外拖放由后续卡处理；不宣称已经完成 Windows 的批量文件拖入。

## 模块与验证

1. **Cocoa 拖放分类**：仅单个存在的常见音频扩展名可进入文件路径；非文件 URL、目录伪装、普通文件或混合项拒绝。失败后原库和原文件保持。只改 Mac 入口及本卡诊断快照，不改 Windows 窗口消息或共享数据库模型。
2. **入库、搜索与试听**：共享快照读取元数据和时长；成功才写库、刷新搜索、预载首个音频并生成波形；重复文件计作已存在；不能读取音频时计作失败并显示提示。输入不复制、不改写源文件。
3. **先写可重复回归，再改产品**：用本卡编译期隔离根创建新库和合成 WAV；通过原生 Cocoa `draggingEntered/performDragOperation` 与私有 NSPasteboard 测试有效/重复/损坏/非音频/无库/繁忙情形，核对 SQLite 行、时长、试听输出、暂停、退出重开和源文件 SHA-256。重跑上卡文件夹及 .db 拖入回归；真实 Finder 鼠标手势仍属用户验收。
4. **交付边界**：Mac Debug 构建、定向测试、内部 ZIP 解压后实测、实际截图及原始日志集中到 `qa/CV-826CF08E/README.md`。仅 Mac 平台层预期改变，仍以同 SHA Windows CI 证明产品可构建与定向回归；非诊断 Release 只编译不接触日常数据。用户确认界面前不合入 QA/main，不对外发布。

## 实测发现的共用缺口

2026-11-04 隔离测试首次在同一素材库中扫描另一目录时，先前手动拖入、位于库根外的音频记录被共享的 `pruneEntriesOutsideLibraryRoots` 删除；Windows `WM_DROPFILES` 也直接 `addFile`，不登记根目录。这不是 Mac 原生拖入分类能独立修好的问题：把音频的父目录擅自登记为扫描根会让将来扫描意外导入兄弟文件。此卡保留原始失败，繁忙测试改用第二个独立库；手动文件的精确范围持久化、刷新总数与两端回归须单独立卡。不能以本卡的重开通过声称“随后扫描其他目录也能保留”。
