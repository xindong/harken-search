# CV-669C1E57 · Mac 音频向外拖放

基线：qa/current 22fcaed3；本卡依赖已提交的 Mac 功能候选 task/CV-F797C36F c812c5e（尚待用户验收，未合入 QA）。卡片与当前 Cindy 会话登记后才开始修改。Windows 需求参考：仓库内 docs/behavior/modules/editor-handoff.md；本次无法直接读取 Windows Cuevi 历史卡，不宣称双向同步。

## 范围和输入输出

- 范围只包括现有列表、文件浏览器和波形选区的“拖出文件”调用到 macOS 原生文件拖放；沿用共用代码生成的原音频或处理后的临时副本，不改音频渲染、搜索、入库、Windows OLE 或界面布局。
- 输入为已准备的本机音频文件路径；原生边界校验路径、文件存在性与数量，向 Finder/DAW 公布 file URL，并只提供复制操作。失败或取消时解除拖放状态、显示真实错误，不发送半成品或把失败渲染偷偷换成源文件。
- 首卡仅验证“把文件提供给系统拖放目标”；DAW 是否接收、插入时间线以及宿主处理由实际安装宿主的人手测，不把系统接受拖放等同于编辑器导入成功。

## 实施与验证

1. 保留现有 Mac“外部拖放不支持”行为的证据，加入 Cocoa NSDraggingSource，在真实鼠标拖动事件中启动原生会话，并处理取消、成功和应用关闭。
2. 编译本机 Intel 应用；以隔离中英文文件验证原生文件 URL、多个文件、无效/不存在路径和取消；运行相关 CTest 与隔离素材库产品启动、试听、关闭和重开，保存真实截图与日志。
3. 修改共用 main.cpp 时，即使只改 Mac 条件分支，也取同一提交的 Windows 产品构建与相关回归。打出可实际启动的内部 QA 包，列出用户在 Finder 和所用 DAW 中逐项检查的步骤。

本卡需要用户确认实际拖放到 Finder/DAW 的结果和测试包体验；确认前停在“待用户验收”，不合入 QA、不对外发布。
