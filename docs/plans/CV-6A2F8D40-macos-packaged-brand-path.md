# CV-6A2F8D40 · Mac 包内品牌资源从任意目录可见

## 问题与来源

2026-11-04，CV-C9014E27 的同一 Mac 应用从源码目录启动时显示正式 HARKEN 字标，从独立 QA 目录启动时只显示备用文字。两份真实截图在 qa/CV-C9014E27/runs/library-001/0005.png 与 runs/theme-002/01-existing-profile/main-window.png。文件已在 .app/Contents/MacOS/assets 中，HarkenSearchIcons.cpp 的 Mac 路径却只检查进程当前目录。lucide.ttf 也只按当前目录查找，存在同类风险。Windows 原本先查可执行文件目录，不动其行为。

本卡基于最新 origin/qa/current 5cf1e27c0bb216301ed5a8fe7669aa7c7c08c15c，再合入已实测的 Mac 整合候选 a670477c297ade4f58552c4276925ce4c85bc974；来源分别是 Windows 列表字号 QA 与 Mac 各功能候选。主模块为 UI 资源，次要边界为 Platform::GetExeDir。只修包内字体、品牌图标/字标和现有 LoadPackagedAsset 的路径，不换图、不改布局/主题、不改 Windows 分支。

## 行为与最小实现

- 输入：Mac 应用可执行文件位置、程序包内资源相对路径、当前工作目录。正常输出：优先从可执行文件相邻的包内资源读取；开发运行时再回退到现有仓库相对路径。路径含中文或空格也应可读取。
- 缺失处理：包内和开发路径都不存在时继续使用原有文字/空纹理回退；不得凭空显示成功，也不得修改用户数据。只加载本来由该 UI 模块请求的既有静态资源。
- 实现：在 HarkenSearchIcons.cpp 中为 Mac 增加与安装布局一致的 exe-adjacent 候选；Windows 预处理分支保持原状。lucide.ttf 同样优先 exe-adjacent，不扩大到其他资源扫描器。
