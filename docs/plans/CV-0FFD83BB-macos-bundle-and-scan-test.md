# CV-0FFD83BB · Mac 应用包身份与扫描暂停回归

## 问题与影响

- 2026-11-05 核对：最新 `origin/qa/current` 为 `22fcaed3f4f8d95fd64c4153d52ddb38b51de7c4`。上一张 Mac 产品候选 `d0e8b21d297230857722bf05896dc0212b113f25` 尚未合入 QA，故本卡从最新 QA 起步，并明确带入该候选后验证真正的 Mac 应用包；不把候选当作已验收成果。
- 先前生成的 `HarkenSearch.app/Contents/Info.plist` 有空的名称、版本与标识。Finder、系统版本信息和未来升级识别缺少稳定身份。
- `TestScanPauseResume` 在 Mac 构建先遇到诊断宏不一致；其目标还无条件链接 Windows 系统库。扫描暂停、恢复与回退因此缺少可运行的 Mac 回归。

## 范围与责任

- 主领域：UI / Mac 应用包的系统呈现；次领域：Indexing 的扫描回归。改动只限 Mac 包元数据、该测试目标的跨平台构建配置和必要的回归证明。依据 `CONTRIBUTING.md`，两个领域的审阅与 Windows 同提交证据均记录在本卡。
- 输入：CMake 项目版本、应用名称、明确的 Mac 包标识，及现有扫描暂停测试源码。
- 输出：实际 `.app` 中非空且一致的名称、版本和标识；`TestScanPauseResume` 在这台 Intel Mac 构建并运行，保留暂停、恢复、回退的断言。
- 失败处理：若元数据缺失或不一致，检查命令返回非零；若扫描测试失败，保留完整编译/运行日志和独立测试库。不得用跳过或空实现伪装成功。
- 非目标：重写扫描逻辑、改变 Windows 包身份、签名公证、自动更新、界面改版、合入 QA 或对外发布。

## 验证顺序

1. 保存原始失败证据；先增加实际包 `Info.plist` 的自动检查，再对旧包运行，确认能发现空字段。
2. 只补 Mac 应用包必要的 CMake 属性，构建产品并检查 `Info.plist`、图标和实际启动/退出。
3. 在隔离构建目录重现 `TestScanPauseResume` 的编译/链接错误；最小化修正目标的宏与平台链接，运行该测试和紧邻扫描回归。
4. 用本卡独立素材、数据库、设置及日志构建、运行真实 Mac 包；记录命令、退出码、截图或明确说明无界面变化。
5. 提交后对同一完整 SHA 取得 Windows 构建及相关扫描回归证据。若远端不可用，明确标记 Windows 未验证，不推进验收。
6. 将包、日志、差异、已知问题和结果集中到 `qa/CV-0FFD83BB/README.md`，写入并回读正式 Cuevi 卡。用户明确确认前不记界面验收通过。
