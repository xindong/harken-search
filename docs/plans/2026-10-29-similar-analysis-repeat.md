# 分析与扫描失败原因，以及独立的扫描结果窗口

## 用户问题

相似音效批量分析走完后，部分文件仍未建立特征；只显示失败总数不能解释原因。普通文件夹扫描也需要完整的失败分类，且扫描进度与结束后的结果不能混在同一个窗口。

## 范围与非目标

- 成功写入有效特征才算分析成功；失败文件仍可重试，不以无效特征凑数量。
- 相似分析分别统计格式不支持、无法读取或损坏、没有可用音频内容、特征保存失败。
- 普通扫描分别统计不可访问、文件不可读取、没有可用音频内容、数据库写入失败、其他错误。分类总数不受最多 32 条详情样例限制。
- 扫描结束且前台收尾完成后，从进度窗口切换到独立结果窗口；结果只显示统计、分类、详情和完成操作。
- 不改变数据库结构、BPM/调性、搜索筛选、取消及切库线程生命周期。

## 模块设计

### 特征提取与批量任务

FeatureExtractor 返回区分原因的错误。批量任务分别检查提取和保存结果，累积分类计数，并在工作线程结束后发布结果。没有失败且未取消才显示全部完成；不把尝试进度冒充成功数量，不保存无效特征。

### 普通扫描与状态发布

ScanStats 保存完整的错误分类计数，多目录扫描合并统计，不可访问的路径产生明确失败。AppState 向界面发布错误快照；新扫描、切库及结果确认时清理相应状态，避免旧计数混入下一次扫描。

### 扫描窗口

- 扫描与前台收尾期间保留进度窗口；过程中发生错误不提前显示结果。
- 失败结束、暂停或取消后，关闭进度窗口再打开独立结果窗口；零文件但有失败也显示结果。
- 只在原窗口仍打开时交接，不通过每帧检测失败数反复打开结果；点击完成后不重弹。
- 成功摘要与快速扫描行为保持不变，原有分类、详情和完成操作保留在结果窗口。
- 中、英、日三种语言使用一致的分类和窗口流程。

## 可重复验证

- tests/test_feature_extractor.cpp：提取失败与格式不支持的结果。
- tests/test_search_workspace.cpp：扫描失败分类、完整计数及重置。
- tests/test_scan_error_snapshot.py：错误快照和编译运行实际 C++ 窗口显示条件，覆盖扫描、收尾、成功、失败、零文件错误、暂停、取消与已确认状态。
- tests/test_scan_quick_start_contract.py：快速扫描原有行为。
- tools/qa_scan_result_windows.py：隔离包扫描 64 个有效样例和 40 个无音频样例，核对完整分类与最多 32 条详情；验证进度与结果分窗、完成后不重弹、重扫计数以及不可访问路径。只通过应用内输入操作，不移动系统鼠标。

本机测试包身份、截图、验收确认、机器路径及真实素材库记录保存在本机验收材料中，不随源码公开。

## 已知限制

不可访问导致零文件时，顶部仍沿用“未找到可识别的音频文件”与递归扫描提示；下方不可访问分类及详情准确。该旧文案未纳入本次分窗修复，不作为已修复成果。
