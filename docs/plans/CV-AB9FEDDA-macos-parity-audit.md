## 模块与验证

1. **核心素材流程：**依据 docs/behavior/module-index.md 和逐模块契约，核对素材库、扫描、搜索筛选、封面、标签、元数据、播放、波形、播放列表和文件浏览。把已有真实应用报告与当前代码版本相互对照；未覆盖的操作只记“未验证”。
2. **系统接口与高级功能：**逐一追查 Windows 界面入口到 macOS 平台实现，包括文件选择、导出、外部拖放、快捷键、音频格式、AI/BPM/调性、工作站连接、授权和更新。空实现或 Unsupported 需指出具体调用路径和用户可见影响；Windows 专属功能要区分“移植缺口”和“不适用于 Mac 的实现形式”。
3. **包与验收：**核对测试包源码身份、资源与原生应用图标、签名状态；用原始日志确认真正运行的功能和退出码。报告按“已实测通过 / 源码确认缺失或无效 / 尚未验证”列出，给每个缺口优先级、独立修复卡建议和验收方法。仅当测试包具有本卡隔离数据根且不影响正在使用的实例时，才增加新的实际运行验证。

## 实际盘点结果

- 本卡读取的 QA 基线仍使用 ImGui Demo 作为 Mac 入口；用户已打开的真实产品包来自尚未整合、尚有未提交内容的独立试听卡。两者不能混成“最新 QA 全功能包”。
- Mac 可见的设置导入、头像图片选择、封面图片导入和选区 WAV 保存均连接返回空路径的平台实现；词库合并的处理主体只在 Windows 编译。Mac 文件夹和数据库选择另有原生实现，不能笼统判定全部失效。
- 现有隔离运行仅验证了小样本库、扫描、有限组合筛选、WAV 试听和波形。元数据编辑、播放列表、封面墙、相似音效、多格式、工作站和更多设置入口仍需单独实测。格式补充解码、工作站进程/管道、AI/BPM/调性及更新/凭据有明确 Mac 实现缺口。
- 当前包内有品牌 PNG，但 Info.plist 没有指定 Finder/Dock 用的原生图标。修复应独立于应用内 Logo 加载。
- 后续优先固定真实产品源码并取得同版本 Windows 回归，再按文件选择、核心行为模块和高级能力逐卡推进。此卡不修改产品行为，也不声称已经完成全功能验收。
