## 来源与现状

2026-11-03 的 origin/qa/current 为 d2d3be8145be5d3142f7cf426fca650bcc519f2e。Mac 差异盘点 CV-AB9FEDDA 指出 M4A 已在素材库扩展名列表中，但 Mac 的 Media Foundation 补充解码实现返回不可用。Windows 的音频和扫描行为以仓库 docs/behavior/modules/audioengine.md 与 scan-indexing.md 为准。真实 Mac 产品入口依赖尚未验收的 CV-38D23BE1 候选 a738a82d6074f25644f6adb7038323f240e32427；纳入本卡分支时记录合并提交，不假定它已进入 QA。

## 范围与顺序

1. 只用隔离目录生成短 WAV 与 Apple 编码的 AAC-M4A、ALAC-M4A。记录当前版本扫描后的元数据、主/列表波形、试听、暂停及跳转结果，坏文件应报错且不沿用前一条音频。额外检查 MP3、FLAC、OGG、AIFF 的现状；发现新缺口时另卡，不能记为本卡已修复。
2. 若 M4A 缺失属实，仅在 Mac 平台补 Probe/Decode，返回平台无关的采样率、声道、帧数和交错 float PCM，支持取消和失败后清空输出。复用现有扫描、波形和播放调用，不更改 Windows 解码和界面。公共调用若有修正，必须用同一提交做 Windows 回归。
3. 用真实产品的隔离库完成扫描、组合筛选、试听/暂停/跳转、主/列表波形和退出重开；同时跑解码边界、损坏文件与 WAV 回归。保存原始命令、错误、截图与实际包身份。输出回调有非零样本只代表程序已向设备提交音频，实体听感仍需用户确认。
4. 将候选包、截图、格式矩阵、日志、SHA 和未覆盖项写入 qa/CV-FA5A6E8E/README.md 并回写 Cuevi。用户验收前不合入 QA、不称完整 Windows 功能版、不对外发布。
