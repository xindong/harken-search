# BUG-20261102-DAY-NAVY-MISMATCH：日夜所选内置主题与直接选择一致

2026-11-02。依据 Cuevi 本卡 revision 2 的已确认范围：白天选深海军蓝应与直接选深海军蓝显示同一套配色；日夜两栏均可选现有五种主题。用户随后补充：日夜模式不能改变用户的默认主题，且默认关闭。只修复主题应用及保存行为，不改五套主题的颜色，也不增加设置项。

## 原因与边界

日夜选择器把五种内置主题的完整配色保存到各自的 JSON 文件。旧的运行时不区分内置主题和用户编辑的配色，统一把当前主题标为 Custom，并直接写入颜色。直接选主题则经过 ApplyTheme，其中还有深海军蓝的专用界面处理。因此颜色数据相同，左侧筛选器等区域仍可能显示不同。修改前的隔离包在五种主题、白天和黑夜共十条路径中都报告 Custom；深海军蓝截图可见差异。

## 分模块设计

| 模块 | 本卡改动 | 独立核对 |
| --- | --- | --- |
| 日夜方案识别 | 初始化或保存日夜 JSON 后，用完整配色逐项比较五种当前内置主题；完全相同才记录对应主题，否则保留为用户自定义。识别结果只缓存于运行时，不改变 JSON 格式和另一时段文件。 | 五种主题逐个选择并回读；已有配色文件读写测试继续通过。 |

| 设置页和隔离验收 | 不改选择器结构及颜色值。隔离脚本通过程序内部测试入口点击五种主题，用独立素材库和私有桌面取实际画面；保留每条命令、截图和退出码。 | 五主题 × 白天/黑夜共十组逐区截图对比；自定义编辑、取消、重启、跨点等原检查继续通过。 |

## 用户补充：默认主题与开关

| 模块 | 具体做法 | 独立核对 |
| --- | --- | --- |
| 配置默认和旧值 | 新安装的日夜模式初始为关闭。旧版关掉勾选时留下的固定白天、固定夜间数值在读取时转成关闭；用户主动启用的自动模式仍保留。 | 默认设置测试和旧数值读取测试。 |
| 日夜运行状态 | 启用时记住当前手动主题及其自定义颜色开关。日夜主题可改变当前画面，但这份手动选择不变；用户手动改主题时才更新它。关闭时恢复手动主题并刷新界面配色。 | 实际包分别切到白天和夜间，关闭开关后核对主题身份和画面。 |
| 设置保存 | 保存设置或编辑日夜配色时，写入记住的手动主题，不把定时画面或编辑预览写成默认主题。日夜配色仍存放在各自的文件中。 | 检查 settings.ini 中的主题值，关闭程序并重开后再次核对。 |

先前交付的测试包在“启用后保留默认主题”检查中复现失败：手动深海军蓝被定时白天主题写成玫瑰雪松。该包和截图只保留为历史证据，须用新候选包重新验收。
