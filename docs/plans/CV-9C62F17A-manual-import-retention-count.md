# CV-9C62F17A · 手动导入的保留与即时计数

## 来源与范围

2026-11-04 从 Mac 卡 CV-826CF08E 的隔离实测接续：拖入一个不在扫描根内的音频后，扫描另一个目录会删掉它；直接入库后数据库与列表有一行，标题计数却为 0，重启后才恢复。原始证据在该卡的 logs/005、logs/007 与最终解压包 report.json。Windows 当前 qa/current 的 WM_DROPFILES 也直接调用共享 Database::addFile，故须改共享语义并跑同提交 Windows 回归，不能只在 Mac 窗口层遮盖。

基线为最新 origin/qa/current 80d40136b2a6c4d5b0c675af06a37f90c68b7bd5。此卡独立 clone/分支先引入上一张尚未验收的 Mac 拖入候选 24ffdfffe5e34b379fa84d1852078d585a185c7c，再在其上修复；候选不等于已合入 QA。

## 模块、失败处理与验证

1. **来源标记**：共享数据库为新手动导入记录持久保存“由用户明确导入”的标记。Mac 单文件拖入与 Windows 小批量文件拖入显式传递标记；扫描入库保持普通来源。扫描前修剪只保留明确标记的单个文件，绝不把整个父目录自动登记成扫描根。已存在记录经用户再次拖入也可标记；旧库中无法判明来源的历史行不自动猜测为手动导入。数据库打开迁移须幂等，取消扫描时须恢复被触及文件的标记。
2. **即时计数**：手动添加或标记时只更新受影响文件夹的 folder_index。实测还发现搜索只读连接的两秒总数缓存没有感知其他连接的提交，且短扫描的 folder_index 可暂时落后；因此全库总数使用 audio_files 的真实 COUNT，并用 SQLite data_version 与本连接 revision 共同失效缓存，避免每帧重复查询。扫描批量 addFile 不承担逐文件重建成本。失败不得伪报成功或留下错误计数。保留现有 upsert、重链和扫描生命周期语义。
3. **先复现后修复**：新的 Mac 隔离流程在同一库中拖入库根外 WAV、确认标题计数、再扫描另一根；核对两条记录和重启恢复，源文件哈希不变。修复前应稳定复现失败。补 Windows 真实数据库回归，覆盖显式导入保留、普通越界记录仍被修剪、重复导入不增数、旧库迁移；在同一提交 Windows CI 构建和运行。
4. **交付**：Mac Debug 隔离构建、CTest、最终 ZIP 解压后的实际运行与截图；非隔离 Release 仅编译；完整原始日志、包和已知限制集中到 qa/CV-9C62F17A/README.md。用户验收前不合 QA/main，不对外发布。
