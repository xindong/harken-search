# Mac 导入 REAPER FileList 到播放列表（CV-A9D5D187）

## 来源与问题

- 基线：2026-11-09 远端 qa/current cfdd64eec1e1115612b3286c4c7591fed5c24c11。Windows 的播放列表菜单可选择 ReaperFileList，调用共用的导入流程；Mac 菜单被平台条件隐藏，文件选择接口返回空路径。
- 本卡只补这项导入，不实现 REAPER 轨道直送、插件、进程连接或其他工作站。输入是用户选中的本机 FileList，输出是当前独立素材库内的新播放列表及其导入结果。取消选文件不得启动扫描或改库；坏文件和缺失素材要保留已有导入错误与计数。

## 实施与验证

1. 用 macOS 原生文件面板返回 UTF-8 文件路径，保持 Windows 和非 Mac 平台的现有行为；在 Mac 显示同一个导入菜单并调用现有异步流程。
2. 先扩充直接相关的边界回归，再运行 Mac 的文件面板探针、共用 FileList 导入测试、平台边界测试和完整产品构建。只使用本卡隔离的合成文件、库、设置和日志。
3. 对共用 main.cpp 或测试契约的修改，取得同提交 Windows 产品构建与相关回归。若当前 qa/current 的 Mac 入口仍是 Demo，则原生面板和数据库测试只能算技术验证；真实菜单点选、截图及用户验收须在整合真实入口的候选包上补做，不以 Demo 代替。

## 交付边界

- 在 qa/CV-A9D5D187/README.md 集中记录提交、包或探针、输入文件、实际测试、错误和未验证项。界面验收前不合入 QA，不宣称工作站直送可用。

## 构建时发现的基线阻塞

- 最新 QA 的 Windows 专属 REAPER Bridge 测试未按平台包围，导致 Mac CMake 配置引用不存在的 DLL 目标；仅为该目标加 Windows 条件。
- 最新 QA 的 AppState.cpp 在 Mac 编译时使用了 Windows 专属的 _TRUNCATE；本卡只复用已在旧 Mac 候选验证过的有界字符串复制写法，使隔离导入测试和产品构建能继续。两处公共文件变更均须由同提交 Windows CI 验证。
- 共用 TestSubPlaylists 目标把 Windows 系统库无条件传给 Mac 链接器；仅将链接库按平台选取，以运行已有的 FileList 实际入库测试。
