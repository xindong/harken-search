# 百万素材库的界面统计卡顿

## 问题与范围

2026-10-30 对一个百万条素材库的隔离副本进行真实 Release 包对照。
相似音效面板每两秒在 UI 线程扫描 `audio_files`，单次约半秒。
第一项修复之后，仍复现空闲自动补全检查缺失波形造成的 19.74 秒停顿；
细分计时显示几乎全部时间在 `countFilesNeedingWaveformCache()`。
两项都属于只读全库统计，不应阻塞界面。

本改动不修改表结构、扫描规则、音频内容、筛选条件或界面布局。
仅把这两条统计路径放到后台，保留统计口径和现有两秒/一分钟刷新节奏。

## 后台统计模块

`LibraryStatisticsWorker` 每个实例只拥有一个线程、一个待执行请求和一个完成结果。
调用者仅交换路径、代际编号和数值；执行 SQL 时不持有交接锁。
每次改变库路径或代际编号，以及关闭/取消时，递增内部请求编号，丢弃旧结果。
完成结果必须仍属于当前请求编号才可发布。相同请求运行时不重复排队。
析构先取消并唤醒线程，再等待退出；处理函数通过取消检查中止 SQLite。

两个工作器由 AppState 持有，处理函数不捕获 AppState、主数据库连接或界面对象。
采用 shared_ptr 作为状态持有器以保持仅测试状态的目标不依赖后台实现链接；
运行时不向其他组件转交其所有权。

## 相似音效统计

工作器只读打开当前 main.db，执行原有音频特征版本统计。每次请求重新打开，
避免同一路径重新建库时继续读取旧文件句柄。SQLite 的进度和等待回调检查取消。
界面每帧只取已完成结果，成功后替换缓存，失败时保留当前库最近的有效值。
切库立即清空旧缓存；隐藏面板或切库取消未完成请求。
两秒节奏按提交时间限速，失败不会变成逐帧重试。

切库时界面先取消两个统计请求；切库后台线程再等待其只读连接真正关闭，
然后才关闭主库、移动旧库目录并打开新库。等待期间拒绝新请求，界面取结果仍不阻塞。
这保证 Windows 覆盖重建不会被尚未退出的统计读取句柄阻碍。

## 空闲补全检查

保留设置中的空闲延迟和每分钟检查节奏。满足条件后只提交只读统计，
后台使用自己的 Database 连接读取缺失波形和待补封面/元数据数量。
界面取得结果后再次检查库身份、空闲状态、播放、扫描和其他补全任务。
用户开始操作、切库、关闭自动补全或失去执行条件时取消检查，旧结果不会启动任务。
检查成功且有欠缺时沿用原来的补全入口；已知波形数量直接传入，避免启动时再扫描一遍。
无欠缺时不启动补全。失败不被当作成功完成。

## 验证

- 可阻塞的测试处理函数证明 Poll/Request 不等待 SQL，重复请求不堆积。
- 不同库、同路径不同代际、关闭面板和退出中止测试。
- 实际 SQLite 的 NULL、特征版本、空库、写入后刷新和缺失文件只读测试。
- 使用真实 SQLite 读取句柄复现 Windows 重命名受阻；确认后台等待连接释放后可重命名，等待期间界面轮询保持非阻塞。
- 原始真实包轨迹作为失败样本，修复包重复三轮开关及保持面板打开的统计暂停/恢复。
- 保留一分钟空闲检查，确认其发生在后台且 UI 不再出现对应长停顿。
- 在同库执行滚动、搜索、标签页、封面及文件夹路径操作，保留响应时间和实际截图。

诊断命令、逐帧轨迹、实际素材库和测试包仅留在本机隔离测试环境，
不作为公开产品内容提交。仓库保留后台统计与界面调用契约的可重复测试。
