# Harken Search 本地方法

这里保存 Harken Search 自己需要的常用工作方法。它们经过项目规则整理，开发时只需要阅读本仓库，不需要再去其他仓库寻找前置说明。

## 按问题选择方法

1. 遇到 Bug、测试失败或结果不对：先读系统排查。
2. 要改代码或补行为：按 TDD 先写会失败的测试。
3. 要说“已修复”“已通过”或准备提交：按完成前验证重新取证。
4. 有用户能看到的页面、弹窗、状态或交互：按界面验收运行实际包并等待用户确认。
5. 要建卡、开独立目录、写进度、留证据或收尾：按 Cuevi 工作流。

## 共同原则

- 先找根因，再改代码；不拿表面提示当结论。
- 一个假设一次只验证一个变量，避免多个修复混在一起。
- 测试、构建、截图和卡片记录都要对应同一份代码和同一份 QA 数据。
- 发现范围外问题时记录下来，不自动塞进当前卡。
- 本地方法文档是项目执行入口；如果仓库内规则与外部资料冲突，以本仓库规则为准。
