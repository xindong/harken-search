# Cuevi 工作流

这份文档把 Harken Search 当前使用的简化流程写成仓库内可执行版本。它只记录当前流程，不恢复旧岗位审批、旧授权 key、固定 QA 槽或旧收口器。

## 开工

1. 查找并复用同一张活动卡，不重复建卡。
2. 确认卡片、活跃会话、分支和独立 clone 都属于当前项目。
3. 从最新 QA 基线建立一卡一分支一 clone；主目录只查看。
4. 在卡片阶段信息中写当前计划、实际改动范围和验收方法。

## 开发

- 只在本卡 clone 中改文件、构建和测试。
- 计划文件放在 docs/plans/，一张卡只维护一份当前计划。
- 阶段信息只写实际发生的结果；待做事项写在下一步，不预填通过。
- 每个重要阶段用正式 Cuevi CLI 写进度，中文正文使用无 BOM UTF-8 文件。
- 遇到阻塞先记录原因和下一步，不私自扩大权限、范围或数据影响。

## 验收和证据

- 纯逻辑改动：记录输入、命令、输出、退出码和未覆盖内容。
- 有界面改动：运行本卡实际 QA 包，保留真实截图，等待用户明确确认。
- 证据附件只上传本卡的测试结果、构建产物或截图，不上传凭据、源代码树或差异文件。
- 逻辑验证和界面确认分开记录；截图存在不等于用户已经通过。

## 合入和收尾

1. 验收通过后按通过时间等待进入 QA 队列。
2. 合入前读取最新 QA，确认本卡变更在合并后的代码上仍能构建和运行。
3. 本地和远端 QA 都确认后，才将卡片推进到完成和归档流程。
4. 保留必要 QA 证据；按项目提供的固定清理工具清理本卡 clone 和分支。

## 发生冲突时

- 先刷新卡片、时间线和当前 revision，不使用旧缓存强行写入。
- 识别为版本冲突、网络不可用、验证失败或命令失败后分别处理。
- 不直接写 Cuevi 数据库。按用户已授权的范围继续执行；需要接续会话时通过正式入口记录归属，不冒用人工身份。
- 任何无法在仓库内证实的内容，都标成未覆盖或待确认。
