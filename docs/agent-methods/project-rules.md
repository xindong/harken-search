# Harken Search 项目协作规则

这份文件是 Harken Search 仓库内的协作入口。项目内规则、计划和方法文档优先于会话外的旧资料；仓库外的文档不能成为本项目继续工作的前置依赖。

## 和用户沟通

- 默认使用简体中文和大白话，尽量少用程序黑话。
- 需求不明确时先问，不猜用户意图；发现真实问题时直接指出，但不借机扩大改动范围。
- 只做当前卡片和当前请求需要的最小范围。
- 回复中说明实际验证结果，不用“应该”“大概”“看起来”代替证据。

## 修改边界

- 主目录只做查看，不在主目录修改产品代码、测试、构建脚本或产品说明。
- 每张 Cuevi 卡使用一个独立 clone 和一个分支；独立 clone 放在仓库外，不新建 Git worktree。分支名使用 fix/卡号 或 task/卡号。
- 改动前确认卡片、独立目录和分支都已经存在，并确认当前会话是这张卡的活跃会话。
- 卡片、阶段、会话、进度和证据只通过正式 Cuevi CLI 或当前接入工具读写；不要直接改 Cuevi 数据库。
- 中文正文先保存为无 BOM 的 UTF-8 文件，再交给正式命令；写完回读，标题或正文出现问号就停止并修正。
- 官网和桌面软件分开开发，不把官网改动混进 Harken Search 卡片或本工作区。

## 计划、模块和文档

- 一张卡只维护一份当前计划；小改动把三句话计划写入卡片，大改动在 docs/plans/ 保存详细计划。
- 需求里分出的模块要在计划或设计文档中分别写清边界、输入输出、失败处理和可独立验证的方法。
- 计划中的事项、实际完成的事项、等待用户确认的事项分开写，不能把待做内容登记成已完成。
- 仓库内文档使用相对路径互相引用；不要把其他仓库的本机路径写进本项目文档。外部资料若有用，先整理成仓库内可独立阅读的内容。

## 测试和验收

- 普通卡优先跑与改动直接相关的测试；只有改动数据库、音频读取、更新、构建底层或正式发布前才跑全量测试。
- 界面测试不得占用用户桌面鼠标；优先使用隔离窗口、QA 命令或隔离数据。
- 有界面表现的改动必须运行本次实际 QA 包，提供能打开实际素材库的截图，并等待用户明确确认后才能记前端验收通过。
- 纯逻辑改动由 AI 设计可重复的验收方法，并记录输入、命令、输出和通过条件。
- 逻辑验证和界面确认分别记录；编译通过不能代替真实功能验收。
- QA 包、日志、截图和独立测试数据放在本机入口指定的卡片专用目录，不放仓库根目录、桌面或下载目录。本机地址与凭据不提交。
- 完成前必须重新运行能证明结论的命令，并检查 Git 差异和工作区状态。

## 收尾边界

- 没有用户确认的界面改动不合并 QA，不把截图存在说成验收通过。
- 不恢复已经淘汰的岗位审批、旧授权 key、旧固定 QA 槽或旧收口脚本。
- 不为了“顺手整理”修改当前卡片之外的产品功能。
- 用户说不需要继续时，用大白话说明做到哪一步并收尾，不追加无关问题。
