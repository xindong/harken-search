# 设置逐项核验007：完整主题编辑

范围：设置的“编辑主题”入口、真实取色器、预览、放弃、保存、关闭、重启，以及编辑器实际提供的 JSON 导入、导出和导入创建。使用独立配置与176个复制音频，本卡不改其他设置功能。

实际发现三项问题：

- 保存后继续改色再关闭：文件仍是保存颜色，主界面却留下未保存预览。native-save-close-before-r2/report.json 为失败证据。原因是关闭逻辑用“本次曾保存”跳过恢复。改为每次关闭普通编辑器都恢复最新保存的快照；保存时同步快照的自定义主题身份。
- 损坏 JSON 也被当成主题导入：旧载入方法使用宽松提取，空数据会被当作默认配色。native-full-r2/report.json 与14-invalid-import截图为失败证据。本卡只在编辑器两个导入入口检查 JSON 对象、至少一个已知颜色键，以及颜色值是6或8位十六进制；保留旧RGB颜色兼容，不改变其他模块使用的旧加载器。合法部分配色文件仍可导入。
- 普通编辑器实时预览开关仅改布尔值，关掉没有恢复，重新开启也不立即显示当前草稿。native-preview-before/report.json 为实际失败证据。关闭恢复打开时的配色；开启立即应用当前草稿，与日夜编辑器的预览行为一致。

测试脚本 tools/qa_settings_full_theme.py 操作真实 ImGui 输入和 Windows 文件窗口；qa_owned_theme_dialog.py 只操作本测试进程所属窗口，并在独立桌面线程内填文件名及确认/取消。导出验证文件与全部保存颜色一致；导入创建验证实际主界面与真实重启。结果文件读取复用本卡测试端 FreshResultDriver，避免旧响应读取挡住 Windows 原子替换。

编辑器观察只在隔离诊断构建启用，返回真实已渲染控件边界，测试不通过观察接口写颜色。18/24px及1120×800/880×600只指设置窗口入口，编辑器本身沿用独立720×760窗口及原有字体。

本机实际包、完整运行结果、失败历史和真实截图位于 D:/Harken-QA/TASK-20261103-SETCHK-007/。前两轮探测使用了错误的控件观察编号，随后改为实际按钮审计；另一次脚本错误把普通主题文件当成日夜配色的嵌套格式。原生文件窗口首次探测读取控件编号1148失败，本机实际为1001，证据均保留。以上测试准备问题与两项实际产品问题分别记录，不能把早期失败标成通过。
