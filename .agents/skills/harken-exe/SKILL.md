# 给我 exe（本卡测试包交付）

目标：用户说一句，就拿到「这次候选的真实可运行包 + 打开位置 + 要看什么」，不再追问路径、数据或截图。

## 做法

1. **确认候选。** 卡号、分支、候选 SHA（`git rev-parse HEAD`）。工作树有未提交改动，先说明并提交到本卡分支，再打包；不打包脏树，也不用旧包或旧截图顶替。
2. **构建。** 在本卡独立目录用 VS 2022 x64 环境（`vcvars64.bat`）加 cmake。首次用某个卡目录先确认 `cmake -S . -B build_debug -G "Visual Studio 17 2022" -A x64` 能配置；配不了就报告缺什么，不反复试。
3. **两种包，别混：**
   - **自验与截图用固定隔离构建**（`-DARIS_PREVIEW_ISOLATION=ON`）。运行根和数据根都是编译期固定值，启动时传 `AURA_RUNTIME_ROOT=<隔离根>/profile/runtime`；换库只能替换隔离根下 `profile/Local/HarkenSearch/Database/<currentDbPath 指向的库>`（连同 `-wal`/`-shm`），并核对 `get_state.db_path` 指向的确实是新根下的库。隔离构建限制素材路径，不适合直接交给用户当「大库」包。
   - **交给用户在真实素材库上试的包**，必须先确认它不会改动用户正式库、配置、Windows 凭据和文件关联：用独立用户资料根、独立关联入口与凭据名、禁用自动更新、独立安装身份。做不到就只交隔离包，并写明它打不开哪些库。
4. **放置。** 包、日志、截图、报告、独立测试数据放 `D:/Harken-QA/<卡号或日期>-<用途>/`，不放仓库根、桌面或下载目录；保留 7 天。
5. **验证包本身。** 运行这个 EXE，核对身份（版本、摘要、`magic_eq_identity` 一类自带入口），再截图。界面自测用私有桌面抓取，不占用用户鼠标；每次先清理本卡目录下残留的 `HarkenSearch` 进程。
6. **本包验收说明面板** 只作本机 QA 打包附加内容，每个包提供自己的说明；不提交、不推送、不合入 `qa/current` 或 `main`。

## 交付说明（一次给全）

- EXE 和压缩包的完整本机绝对路径（交付前核实文件存在并能运行）、SHA-256（小写）、候选 SHA、分支、构建时间。
- 打开哪份素材库（路径），它是副本还是正式库；包是否会写正式库。
- 要看的页面、状态、按钮和预期结果。
- 本次实际包的真实截图，不用设计稿、模拟图、旧包截图；记录包路径、数据路径和操作结果。
- 已完成的自验与未覆盖项；失败要如实写。
- 有 HTML 验收报告时：基础样式在前、深色覆盖在后，加 `<meta name="color-scheme" content="light dark">`，生成后自己核对明暗两套的文字对比度再交。多张卡同时待验收，用一个统一验收页，每项写清改了什么、看什么、包的完整路径、对应的真实截图。

## 边界

AI 自验通过不等于「前端验收通过」：必须等用户看过截图或包后明确确认，才在卡上记录确认原话、时间、包和代码身份。用户明确说当前包通过后，不再为这次验收额外索要截图，直接走 Cuevi 的验收收尾技能（由 cuevi-workflow 插件提供，改名 cuevi-acceptance-closeout）。
